## MiMo TTS 400 错误排查(AI 伙伴语音播报)
- 现象: AI 伙伴触发时 `synthesizeStreaming` 报 `TTS API error 400`,voice=mimo_default。
- 核实官方文档 (mimo.mi.com/docs/zh-CN/usage-guide/speech-synthesis-v2.5):
  - `voice: mimo_default` 合法;流式必须 `audio.format: "pcm16"`(24kHz PCM16LE mono)——现有代码这两处都对。
  - 官方 curl 示例只用 `api-key` header;代码里流式请求同时发了 `api-key` + `Authorization: Bearer`,非流式只发 `api-key`——疑似双 header 触发网关 400。
- 修改 `MiMoTtsClient.kt`:
  1. 流式请求去掉 `Authorization` header,与官方示例一致。
  2. 400 异常信息现在携带服务器返回的错误 body(截断 500 字符),因为用户 logcat 只过滤 AiCompanionManager tag,之前看不到 MiMoTtsClient tag 下的错误详情。
- 待验证: 重新编译安装后再触发一次,新日志会带服务器具体错误信息(若仍 400,大概率是 API Key/账户问题)。

## 陪伴不说话的真正根因(文本生成全挂)
- 日志里 `Generated text is null/blank, skipping TTS` 才是主因:文本生成走 AiOrchestrator,`buildProviderChain(userProvider)` 把「AI 集成」里配的主 provider 放第一。日志第一条失败的是 CUSTOM → 用户主 provider = CUSTOM(自定义 OpenAI 兼容端点)。
- 其余 provider 全部 `no API key`,DeepSeek 402 余额不足。CUSTOM 一旦首次失败就被记 5 分钟 cooldown,之后每次切歌 CUSTOM 在冷却里被跳过,其余没 key → 直接放弃。
- 改法 `AiCompanionManager.kt`: 陪伴文本生成从 `generateContent`(全链兜底)改为 `generateWithPrimaryProvider`(只用 AI 集成的主 provider,无 cooldown 屏蔽、无空 provider 兜底),并把真实报错打进 AiCompanionManager 的日志,便于定位 CUSTOM 配置错误(Base URL 通常要带 /v1 且不要含 /chat/completions;model 名要准确)。
- 注: gradlew 在本机(Git Bash/Windows,缺 cygpath)无法编译验证,需用户在 Android Studio 里 build。

## TTS 400 真正原因定位(续)
- 用户最新日志: `TTS API error 400: {"error":{"code":"400","message":"Unsupported model unknown-model"}}`。文本生成已通(出现了 Companion text)。
- 实测 `api.xiaomimimo.com/v1/chat/completions`: 端点先校验 api-key 再校验 model;假 key 一律 401(不论 model 写啥),有效 key 才走到 model 校验。故该 400 说明请求带着有效 key 且服务器“看到”的 model 字面量就是 `unknown-model`。
- 但代码 MODEL_ID 只有一处 = "mimo-v2.5-tts"(官方文档同名),全工程搜不到 unknown-model 字符串 → 矛盾。两种可能:(a) App 实际发出的 body 与预期不同;(b) 用户账号/集群端点不认 mimo-v2.5-tts。
- 已在 MiMoTtsClient 异常里附带实际 Request URL + Request body,便于从用户可见的 "Streaming playback failed" 日志定位。同时建议用户用本地 curl + 自己的 key 验证 model 是否被账号接受(避免透露 key)。

## 根因确认 + 修复(决定性)
- 用户贴出实际 Request body: `{"messages":[...],"audio":{}}` —— `model` 字段完全缺失,`audio` 是空 `{}`(format/voice 也丢了)。服务器因此用 `unknown-model` 兜底 → 400。
- 根因: kotlinx-serialization 在本项目构建里,带默认值的字段(且传入值恰等于默认值)被整体省略(encodeDefaults 实际为 false 行为)。`model="mimo-v2.5-tts"`、`audio.format="pcm16"`/`voice="mimo_default"`、`stream=true` 全是默认值 → 序列化塌陷。
- 修复 `MiMoTtsClient.kt`:
  1. `Json { ... encodeDefaults = true }` —— 强制写出所有默认值字段。
  2. 两处 `TtsRequest(...)` 构造显式传入 `model = MODEL_ID` 与 `stream`,双重保险。
- 预期修复后 body 应为 `{"model":"mimo-v2.5-tts","messages":[...],"audio":{"format":"pcm16","voice":"mimo_default"},"stream":true}`,服务器即能识别模型。

- 队列来源 `_playerUiState.value.currentPlaybackQueue`(ImmutableList<Song>),时长 `stablePlayerState.totalDuration`,索引 `currentMediaItemIndex`。
